# S1 logs at the 50 GiB default cap, COLD page cache (plan item 0.15,
# issue #60, part 2), 2026-10-20
#
# Machine: Allens-Mac-mini, Apple M4 Pro (12 cores), 64 GiB RAM,
#   macOS 27.0.1, APFS. SAME host as the 2026-10-08 warm runs, but the
#   database ran on the external USB SSD (/Volumes/Development, ESD-S1C,
#   APFS, 931 GiB, ~480 GiB free) because the internal volume had only
#   59 GiB free for a 53.6 GiB file. The USB disk's durable commits cost
#   ~110 ms (see b2g-warm below) vs ~8 ms on the internal SSD: every
#   commit number below carries that disk penalty on top of any cache
#   effect. Reads are unaffected (replay warm matches the 10-08 numbers).
# Go 1.27.2 darwin/arm64, modernc.org/sqlite v1.60.1 (SQLite 3.53.4).
# Code: origin/main at 01c49567 plus the uncommitted drive-60 work (no
#   spike change; S1 built with the default toolchain, cgo on as in S1).
# Pragmas: S1 defaults (WAL, synchronous=FULL, fullfsync=1,
#   busy_timeout=5000, journal_size_limit=64 MiB, auto_vacuum=INCREMENTAL),
#   chunk 2048 B, dur 60 s for the 50 GiB runs.
#
# Procedure (04 "Not proven"): prefill and measure as separate processes
#   with the -reuse flag (added for #60 in PR #242). No purge available
#   (no sudo on this host), and the 53.6 GiB file fits in the 64 GiB RAM,
#   so the cache was cycled by random reads instead: after prefill, 84 GB
#   of random 1 MB preads over a 97 GB scratch file (2.6x RAM of newer
#   distinct pages; `vm_stat` showed 86 MB free at the measuring start),
#   then the -reuse run immediately. Streaming 91 GB reads did NOT evict
#   (macOS keeps recently-written file pages past sequential scans); the
#   random pass demonstrably cycled the whole cache (free 38 GB -> 86 MB).
# Instrument note: /usr/bin/time -l reported 0 block input operations for
#   EVERY run including the cold ones, so the counter is not a working
#   coldness instrument on this host. Coldness is proven three other ways:
#   (1) the LRU argument above, (2) per-disk traffic during the cold
#   50 GiB run (~25 GB on disk6 across its 174 s: vacuum rewrites the
#   whole file, prune scans it), (3) the latency signature: replay p50
#   10x and vacuum 2.4x above the same-disk warm reference below, while
#   fsync-dominated commit p50 is identical (112 vs 106 ms). A warm file
#   on this disk cannot produce 140 ms median session replays.
# Other load: none; the measurer owned the machine (load 1.1 to 3.2).
#
# Build:  cd spikes/sqlite && go build -o /tmp/s1-cold60 .   rc=0
# Runs, in order (measuring runs each wrapped in /usr/bin/time -l):
#   /tmp/s1-cold60 -driver modernc -scenario logs -prefill 12900000 -prefill-only -dir <usb>/b50g-cold
#   (random-read eviction, 84 GB) + -reuse on b50g-cold            (COLD 50 GiB)
#   /tmp/s1-cold60 -driver modernc -scenario logs -prefill 500000 -dir <usb>/b2g-warm     (WARM 2 GiB)
#   /tmp/s1-cold60 -prefill 500000 -prefill-only -dir b2g-cold; evict; -reuse on b2g-cold (COLD 2 GiB)
#   /tmp/s1-cold60 -prefill 12900000 -prefill-only -dir b50g-warm; -reuse on b50g-warm     (WARM 50 GiB)
#
# Pass per 04: commit p99 <= 250 ms; every commit, prune tx and vacuum
# step under 1 s; replay 1 h p99 <= 1 s; offset lookup p99 <= 100 ms.
# Result: ALL PASS on the cold 50 GiB run (maxima: commit 182 ms,
# prune tx 58 ms, vacuum step 182 ms, replay 181 ms, lookup 1.6 ms).
#
# 04's "in the thousands, not 0" block-count form of the pass is NOT met
# as written (counter reads 0 on this host); the three proofs above
# stand in its place and are recorded here.
